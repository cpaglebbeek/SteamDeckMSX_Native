# v0.2.1-KingsValley — bundle-verificatie: van "gebouwd" naar "bewezen"

## Trigger

"verder met steamdeck native" — opgepakt na de sessie die eindigde met de BUG-016-fix
(commit `cc13441`, 20:07) zonder dat het resultaat op het artefact was gecontroleerd.

## Beginstand

De HC55-rebuild na de BUG-016-fix bleek al klaar (bundle 18:16 UTC, gehost 18:18 in
`/srv/steamweb/flatpak/`). Bron op HC55 bevatte de fix (`URI SteamDeckMSX.Core` +
`IMPORTS` in `src/CMakeLists.txt`). ClaudeBug-inbox: 2 foto's van vandaag, beide al
verwerkt (BUG-015 om 19:40, BUG-016 om 19:56). Geen nieuwe Deck-feedback.

## Kernvraag

BUG-016 was op Mac gefixt met `QT_QPA_PLATFORM=offscreen`. Maar de Mac draait Qt 6.11 en
de bundle draait op de KDE-runtime 6.7 — en juist 6.7 gaf de *harde* fout op het
duplicate `closed()`-signaal. Een groene Mac-launch bewijst dus niets over de bundle.
Er is geen SSH naar de Deck (die loopt via clipboard + ClaudeBug-foto's), dus de
verificatie is naar HC55 gehaald: x86_64 Linux met dezelfde flatpak 1.14.6 en dezelfde
KDE-runtime 6.7 als de Deck.

## Uitgevoerd — 4 gates, alle groen

1. **Install** — `flatpak install --user` op HC55. Eerst blokkeerde
   "already installed": zonder geforceerde uninstall test je stilzwijgend het *vorige*
   artefact. Uninstall + install: groen.
2. **App-launch offscreen** — 20s stabiel, **nul regels output**. Met
   `QT_LOGGING_RULES=qt.qml.*` zichtbaar: `SteamDeckMSX.Core` wordt correct als
   dependent import geladen, `Main.qml` resolvet. BUG-016 bewezen weg in het artefact.
3. **C-BIOS-boot** — openMSX in de sandbox op een eigen Xvfb `:99` (`:0` is van
   Sunshine/Stream_Server — bewust niet aangeraakt). Screenshot toont "C-BIOS 0.29 /
   cbios.sf.net / Init ROM in slot 3.1 / No cartridge found". Bewijst de hele
   BUG-012/BUG-004-keten (share-tree + `OPENMSX_SYSTEM_DATA` + locator-layout) op runtime.
4. **Cartridge end-to-end** — `-carta nemesis2.rom` (uit
   `/var/lib/steamdeckmsx/roms/`, van Stream_Server). Eerste poging op t=10s gaf een
   leeg blauw scherm; meerdere tijdstippen bemonsterd wees uit dat dat gewoon *tussen*
   twee scènes viel. t=7s: Konami-logo. t=18s: intro-cutscene met tekst. Mapper-detectie
   werkt dus ook.

## Les (geborgd in BUGLIST BUG-016)

Een fix valideren op het dev-platform is géén validatie van het distributie-artefact.
Runtime-Qt, flatpak-versie en sandbox-layout verschillen. De gate draait daarom op een
host die de doelomgeving nabootst, en test de bundle na een schone herinstall.

## Volgende actie (user, op de Deck)

De bundle op de Deck is nog de oude (pre-BUG-016). Opnieuw downloaden en installeren:

```bash
# Op de Deck, Desktop Mode, Konsole:
cd ~/Downloads
rm -f SteamDeckMSX-v0.2.1-KingsValley.flatpak
curl -LO https://horsecloud55.ddns.net/steam/flatpak/SteamDeckMSX-v0.2.1-KingsValley.flatpak

# oude install eerst weg (anders "already installed" en je test de oude!)
flatpak uninstall --user -y nl.icthorse.SteamDeckMSX

# flathub-remote is al toegevoegd in de vorige sessie (BUG-015-workaround);
# de bundle draagt de runtime-herkomst nu zelf mee
flatpak install --user -y SteamDeckMSX-v0.2.1-KingsValley.flatpak

# starten
flatpak run nl.icthorse.SteamDeckMSX
```

Te testen op de Deck: start de app zonder QML-fouten → C-BIOS-boot → ROM via URL
downloaden in de UI → gamepad-input → Gaming Mode. Foutmeldingen via ClaudeBug (foto),
dan `/bugcheck`.
