# v0.2.1 — Mac smoke-test + compile-fixes + auto-setMachine + commandFinished + tests backfill

> Vervolg op v0.2.0-TreasureOfUsas (2026-06-08). v0.2.0 leverde 7 features via
> 4 parallelle agents + solo orchestratie, **zonder Mac smoke-test** (per
> user-instructie). v0.2.1 is "verifieer + polish".

## Pre-conditie (KRITISCH)

```bash
cd /Users/christian/Documents/Gemini_Projects/SteamDeckMSX_Native
cmake --preset native-debug -DSTEAMDECKMSX_BUILD_TESTS=ON -DSTEAMDECKMSX_VERSION_CODENAME=TreasureOfUsas

ctest --output-on-failure
```

**Verwacht**: 100% / 5 binaries / 40+ testcases (4 oude + test_softwaredb 6 nieuw + romtypedetector 11→13). Bij fout: compile-fix vóór nieuwe scope.

**Bekende risico's** (van v0.2.0 zonder-build-besluit):
- `Qt6::GuiPrivate` link — Qt6 6.11 op Mac dev kan extra `find_package` argumenten vereisen
- `<QtGui/private/qzipreader_p.h>` include-pad kan platform-afhankelijk zijn
- SaveStateModel `requestThumbnail` aanroep van `m_core->state()` — `MsxCore::State`-enum check kan `using enum` vereisen of fully-qualified naam
- SoftwareDb namespace-collisions met bestaande code (geen verwacht maar zelf nooit gebouwd)
- Main.qml `BiosZipExtractor`/`SoftwareDb` QML-type-registratie — mogelijk import nodig

## Scope v0.2.1

### 1. Mac smoke-test + compile-fixes

Draai bovenstaande build. Bij elke fout: minimale fix. Maak van elke fix een BUG-entry in BUGLIST.md met kleurcode + RCA.

### 2. Auto-`setCurrentMachine` via SoftwareDb-lookup

In `MsxCore::loadRom` (bestaande log-only sinds v0.0.8): na SHA-1 berekening, doe `softwaredb.lookupMachine(sha1)`. Als niet-leeg: `setCurrentMachine(result)` + toast.

Voorwaarde: accuratesse-rapport over ≥10 ROMs (manueel testen, log verzamelen). Aangezien de bootstrap-data slechts 5 sample-entries heeft, eerst real `softwaredb.xml` van openMSX installeren — Linux Flatpak heeft `/app/share/openmsx/softwaredb.xml`.

### 3. `commandFinished` signal vanuit MsxCore

Reden: thumbnails async-race (DD-113 uit v0.2.0).

`MsxCore` houdt al `m_nextCommandId` bij. Bij elk antwoord van openMSX op een `<reply>` parsen we al een id. Emit:
```cpp
void commandFinished(int commandId, bool ok, const QString &body);
```

`SaveStateModel::requestThumbnail` onthoudt de commandId, koppelt aan timer of slot in `m_pendingThumbCmds[commandId] = slot`. Bij `commandFinished(id, ok, body)`: als `id == pending`, emit `dataChanged({ThumbnailPathRole})` om Image-reload te forceren.

### 4. Slot B-floppy UI

`SlotPickerDialog` uitbreiden met 4 opties:
- Slot A (ROM cart)
- Slot B (ROM cart)
- Floppy A (Disk drive 0)
- Floppy B (Disk drive 1)

Detecteer media-type uit current cartridge → pas labels aan.

### 5. Drag-and-drop MIME-type-detect

Huidige drop-handler: `if (lower.endsWith(".zip")) ...`. Verbeter met `QMimeDatabase::mimeTypeForFile`:
- `application/zip` → BiosZipExtractor
- `application/x-rom` of `.rom` extensie → BiosManager.addFromLocal
- Onbekend → toast warning

### 6. Unit-tests backfill

Schrijf testen voor:
- `BiosManager` — fixture `.rom` files in `tests/data/`, addFromLocal + persist roundtrip + remove + clear
- `FileDownloader` — mock-NAM patroon (subclass QNetworkAccessManager + override get)
- `SaveStateModel`-thumbnails — slot + thumbnailPath roundtrip via QSettings (mock-core)
- `BiosZipExtractor` — fixture ZIP met 3 files (1 OK, 1 te groot, 1 unsafe path), verifieer counts
- `MsxCore`-DSK/CAS-API — signature-test (loadDsk niet-Running → -1)
- `CartridgeModel::mediaTypeFor` — diverse extensies + fallback

### 7. ROM-header parse publisher/year (uit v0.1.1-uitstel)

Heuristiek op offset 0x10..0x20 voor copyright-string. Voeg `publisher` + `year` velden toe aan CartridgeEntry. Default: lege string (geen detectie).
